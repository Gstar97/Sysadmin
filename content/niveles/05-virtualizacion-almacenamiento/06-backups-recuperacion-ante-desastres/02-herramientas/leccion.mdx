Con la estrategia armada, hace falta elegir con qué. No hay una herramienta para todo: las VM se respaldan con la del hipervisor, los archivos con una herramienta de archivos, y las bases de datos, con su propio volcado. Lo que tienen en común las buenas es la forma de guardar.

## Cómo se guardan las copias

<DiagramaInteractivo datos={tiposDatos} svg={tipos} alt="Cuatro filas, de lunes a jueves, con 500 GB de datos que cambian 60 GB por día. Completa cada vez: 500 GB cada día, 2 TB guardados, para restaurar alcanza una copia. Incremental: 500 GB el lunes y 60 GB cada día siguiente, 680 GB, pero para restaurar el jueves hacen falta las cuatro. Diferencial: 500 GB el lunes, y 60, 120 y 180 GB, 860 GB, y para restaurar alcanzan la del lunes y la del jueves. Deduplicada: cada día una copia completa en la que solo se guarda lo nuevo, 680 GB, y para restaurar alcanza una copia." />

Dos cosas más que importan al elegir:

- **Cifrado del lado del cliente**: restic, Borg, Kopia y PBS (con clave de cifrado) cifran antes de mandar, así que el servidor de respaldo (o el proveedor de la nube) guarda datos que no puede leer. Si se pierde la clave, se pierde todo.
- **Copias consistentes**: respaldar un archivo mientras se escribe da una copia rota. Las VM se respaldan con una instantánea (y el agente de invitado congela el disco un instante); las bases de datos, con su volcado; y los archivos, mejor desde una instantánea de ZFS o LVM si cambian mucho.

## El mapa de herramientas

| Para qué | Herramientas | Notas |
|---|---|---|
| VM y contenedores de Proxmox | vzdump + Proxmox Backup Server | Incremental para siempre, deduplicado, verificable; restauración de archivos sueltos y en vivo. |
| VM de VMware o Hyper-V | Veeam Backup & Replication, Nakivo | Veeam también respalda Proxmox desde la versión 12.2. Se paga por máquina o por socket. |
| Archivos de Linux | restic, BorgBackup, Kopia | Deduplicados y cifrados; restic y Kopia hablan con S3 directamente. |
| Archivos y servidores Windows | Windows Server Backup, Veeam Agent | WSB alcanza para un servidor; para varios, algo centralizado (lección 3.5.5). |
| Bases de datos | mysqldump, pg_dump, Percona XtraBackup, pgBackRest | El volcado se respalda después con la herramienta de archivos (lección 4.3.4). |
| Servicios en la nube | las del propio proveedor o terceros | Microsoft 365 y Google Workspace no son un respaldo por sí solos. |

## Manos a la obra: restic

restic es un programa solo, sin servidor propio, que guarda copias deduplicadas y cifradas en una carpeta, por sftp, en un **rest-server** o en almacenamiento de objetos S3. El rest-server tiene una opción que vale oro contra el ransomware: **--append-only**, que deja agregar copias pero no borrarlas.

<Terminal ejercicio={ejRestic} />

Para que corra solo, va en un timer de systemd (lo viste en la lección 1.3.4) y, sobre todo, **con aviso si falla**: el respaldo que deja de andar sin que nadie se entere es el problema más común de todos. Lo más simple es que el script avise al monitoreo (o a un servicio tipo healthchecks) cada vez que termina bien, y que el monitoreo grite si un día no llega el aviso.

## Manos a la obra: Proxmox Backup Server

En la lección 5.2.4 armaste las copias de Proxmox a PBS. Ahora, lo que se hace con ellas una vez que se acumulan:

<Terminal ejercicio={ejPbs} />

En el propio PBS hay cuatro tareas programadas que conviene tener:

- **Prune**: la retención (la que hiciste recién, pero automática).
- **Garbage collection**: libera el espacio de los pedazos que ya no usa ninguna copia. Sin ella, el prune no libera nada.
- **Verify**: relee las copias y comprueba que los pedazos estén sanos (lo vas a usar en la lección 5.6.4).
- **Sync**: copia el datastore a otro PBS, por ejemplo en otra sede. Si el PBS remoto es el que *trae* las copias (pull) y el de la sede no tiene permiso para borrar allá, esa copia queda a salvo de un ransomware que entre a la sede.

<EnSimple>
Las herramientas actuales guardan las copias partidas en pedazos y cada pedazo una sola vez: cada noche viaja solo lo nuevo, pero cada copia sirve sola para restaurar. Las VM de Proxmox se respaldan con PBS; los archivos de Linux, con restic o similares; las bases de datos, con su volcado; Windows y VMware, con sus herramientas o con Veeam. restic contra un rest-server "solo agregar" deja hacer copias pero no borrarlas: la limpieza se hace desde el servidor. Y en PBS se programan la retención, la limpieza de espacio, la verificación y la copia a otro PBS.
</EnSimple>

<ErroresComunes>
  <ErrorComun titulo="Respaldar los archivos de una base de datos corriendo">
    La copia puede no arrancar. Volcado consistente (o la VM entera con el agente de invitado) y después la copia de archivos.
  </ErrorComun>
  <ErrorComun titulo="Copias incrementales sin completas nuevas">
    Con incrementales clásicas, una sola copia dañada rompe todas las siguientes. Las deduplicadas no tienen ese problema.
  </ErrorComun>
  <ErrorComun titulo="Prune sin garbage collection en PBS">
    Las copias desaparecen de la lista pero el disco sigue lleno: el espacio lo libera la garbage collection.
  </ErrorComun>
  <ErrorComun titulo="Que el cliente pueda borrar sus propias copias">
    Si el servidor respaldado puede borrar, un ransomware en ese servidor también. Solo agregar, y la retención desde el lado del respaldo.
  </ErrorComun>
  <ErrorComun titulo="Respaldos sin aviso cuando fallan">
    Dejan de andar en silencio y se descubre el día que hacen falta. Avisar cuando terminan bien y alertar si un día no llega el aviso.
  </ErrorComun>
</ErroresComunes>

<Resumen>
- Completa, incremental, diferencial y deduplicada (incremental para siempre): la última es la de PBS, restic, Borg y Kopia.
- Cifrado del lado del cliente y copias consistentes (instantánea, agente de invitado, volcado de la base).
- restic: init, backup (--tag, --exclude), snapshots, diff, forget con --keep-* y --prune, restore.
- rest-server --append-only --private-repos: el cliente agrega, la retención se aplica en el servidor.
- PBS: prune, garbage collection, verify y sync; copias protegidas para los cambios grandes (protegida no es inmutable).
</Resumen>
