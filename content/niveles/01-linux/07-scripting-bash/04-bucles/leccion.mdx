## Tres formas de repetir

Pensá en lavar los platos: uno por uno hasta que no queden (eso es un **for** sobre una lista); seguir mientras haya platos en el fregadero, aunque alguien vaya trayendo más (un **while**); o esperar en la puerta hasta que llegue el cartero (un **until**). Bash tiene las tres.

## for: una vez por elemento

```bash
for s in web01 web02 db01; do echo "Revisando $s"; done   # una lista fija
for f in /var/log/app/*.log; do gzip "$f"; done            # archivos (comodín)
for i in {1..5}; do echo "Vuelta $i"; done                 # un rango
for u in "${usuarios[@]}"; do id "$u"; done                # un arreglo
for ((i = 1; i <= 10; i++)); do echo "$i"; done            # estilo contador
```

Dos detalles con los comodines: si no coincide ningún archivo, bash deja el patrón tal cual (el bucle recibe literalmente `/var/log/app/*.log`). `shopt -s nullglob` hace que, en ese caso, la lista quede vacía. Y poné siempre `"$f"` entre comillas.

## while read: una vez por línea

```bash
while read -r linea; do
  echo "procesando: $linea"
done < servidores.txt
```

Es la forma correcta de recorrer un archivo: respeta los espacios de cada línea. Para separar campos, `IFS` dice cuál es el separador:

```bash
while IFS=, read -r usuario nombre depto; do
  echo "$usuario va a $depto"
done < <(tail -n +2 empleados.csv)      # tail -n +2: desde la línea 2 (sin el encabezado)
```

`< <(comando)` le pasa al while la salida de un comando. No uses `comando | while ...` si después necesitás las variables: cada parte de una tubería corre aparte, y lo que el while cambie se pierde al terminar (lo vas a ver en el ejercicio).

<EnSimple>
Para archivos y listas, `for`. Para recorrer las líneas de un archivo, `while read -r ... done < archivo`. Y nunca `for linea in $(cat archivo)`: parte también en cada espacio.
</EnSimple>

## while y until: según una condición

```bash
until ping -c1 -W1 db01 &>/dev/null; do    # mientras falle
  echo "Esperando a db01..."
  sleep 5
done

intentos=0
while (( intentos < 3 )); do               # mientras se cumpla
  ((intentos++))
  ...
done
```

Un bucle que espera algo tiene que tener un límite (cantidad de intentos o tiempo máximo): si la condición nunca se da, el script queda colgado para siempre. Si eso te pasa en la terminal, Ctrl+C lo corta.

## break y continue

- `continue`: termina esta vuelta y pasa a la siguiente (por ejemplo, para ignorar comentarios).
- `break`: sale del bucle (por ejemplo, cuando ya encontraste lo que buscabas).

```bash
while read -r s; do
  [[ -z $s || $s == \#* ]] && continue     # líneas vacías y comentarios
  ping -c1 -W1 "$s" &>/dev/null || echo "$s no responde"
done < servidores.txt
```

<Resumen>
- `for x in lista; do ...; done`: palabras, comodines (`*.log`), rangos (`{1..5}`), arreglos (`"${a[@]}"`), o `for ((i=0; i<n; i++))`.
- `while read -r linea; do ...; done < archivo`; con campos: `while IFS=, read -r a b c`. Desde un comando: `done < <(comando)`.
- `comando | while ...` pierde las variables al terminar.
- `while cond` repite mientras se cumpla; `until cond`, mientras falle. Siempre con un límite.
- `continue` salta a la vuelta siguiente; `break` sale del bucle.
- `shopt -s nullglob` para que un comodín sin coincidencias no deje el patrón literal.
</Resumen>
