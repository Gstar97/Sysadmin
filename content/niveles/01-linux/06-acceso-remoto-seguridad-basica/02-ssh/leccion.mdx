Casi nunca vas a estar sentado frente a un servidor: están en un centro de datos, en la nube o en otra oficina. La herramienta para trabajar en ellos es **SSH** (Secure Shell): te da una terminal en el otro equipo, como si estuvieras ahí, y todo lo que viaja va cifrado.

<AntesDeEmpezar>
- IP, puertos y cómo diagnosticar una conexión (lección 1.6.1).
- Servicios con systemctl y registros con journalctl (lecciones 1.3.3 y 1.3.5).
</AntesDeEmpezar>

## Qué pasa al conectarte

Pensá en una llamada al banco. Antes de darle tus datos a quien te atiende, querés estar seguro de que llamaste al banco y no a un impostor; después, el banco necesita estar seguro de que sos vos. SSH hace las dos cosas, en ese orden: primero el servidor demuestra quién es, y recién después vos. La diferencia con el teléfono es que todo va cifrado: aunque alguien escuche la línea, no entiende nada.

<Ordenar ejercicio={orden} />

```bash
ssh ana@web01              # usuario@servidor
ssh web01                  # si tu usuario se llama igual en los dos lados
ssh -p 2222 ana@web01      # si sshd escucha en otro puerto
ssh web01 df -h /          # ejecutar un solo comando y volver
exit                       # (o Ctrl+D) cerrar la sesión
```

Después de conectarte, el prompt cambia: `ana@web01:~$`. Acostúmbrate a mirarlo antes de cada comando importante. "Reinicié el servidor equivocado" es un clásico que se evita leyendo el prompt.

## La huella del servidor y known_hosts

La primera vez que te conectás a un servidor, ssh no lo conoce y te pregunta:

```text
The authenticity of host 'web01 (192.168.10.20)' can't be established.
ED25519 key fingerprint is SHA256:UBAFTwUN4SzrA2aL394IQoCiKtXGrpzQHnrKnMoi9ZH.
Are you sure you want to continue connecting (yes/no/[fingerprint])?
```

La **huella** (fingerprint) es un resumen corto de la clave del servidor. Lo correcto es compararla con la que te pasó quien instaló el servidor (en el servidor se ve con `ssh-keygen -l -f /etc/ssh/ssh_host_ed25519_key.pub`). Si respondés `yes`, ssh la guarda en `~/.ssh/known_hosts` y, de ahí en adelante, la compara sola en cada conexión.

Si un día la clave no coincide, ssh se niega a conectar con un aviso enorme (`REMOTE HOST IDENTIFICATION HAS CHANGED`). Hay dos explicaciones: alguien se está haciendo pasar por el servidor, o el servidor se reinstaló (o le cambiaron la IP a otro equipo). Antes de seguir, averigua cuál. Si es una reinstalación confirmada, borra solo la línea vieja:

```bash
ssh-keygen -R web01        # borra web01 de known_hosts (deja una copia en known_hosts.old)
```

<EnSimple>
known_hosts es tu lista de "servidores que ya conozco y su cara". Si un servidor aparece con otra cara, ssh no te deja pasar hasta que confirmes qué pasó.
</EnSimple>

## Del lado del servidor: sshd

El que atiende las conexiones es el servicio **sshd**, que viene instalado en casi cualquier servidor Linux.

| | Rocky | Ubuntu |
| --- | --- | --- |
| Servicio | `sshd` | `ssh` |
| Configuración | `/etc/ssh/sshd_config` y `/etc/ssh/sshd_config.d/*.conf` | igual |
| Registro | `journalctl -u sshd`, `/var/log/secure` | `journalctl -u ssh`, `/var/log/auth.log` |

En el registro aparecen todas las entradas y los intentos fallidos:

```text
Accepted password for ana from 192.168.10.5 port 51432 ssh2
Failed password for invalid user admin from 203.0.113.50 port 40112 ssh2
```

Si tu servidor tiene el puerto 22 abierto a internet, vas a ver cientos de intentos de cuentas como `admin`, `root` o `test` todos los días: son robots que prueban contraseñas. Es una de las razones para usar claves en lugar de contraseñas (próxima lección).

La configuración de sshd tiene opciones como `PermitRootLogin` (si root puede entrar directo) o `PasswordAuthentication` (si se aceptan contraseñas). Las vas a cambiar en la lección siguiente, con un cuidado especial: si te equivocas, podés dejar a todos sin acceso.

<Resumen>
- `ssh usuario@servidor` abre una terminal remota cifrada; `ssh servidor comando` ejecuta un solo comando; `exit` vuelve.
- Primero se identifica el servidor (huella guardada en `~/.ssh/known_hosts`), después vos.
- Clave cambiada: averiguá por qué; si es una reinstalación confirmada, `ssh-keygen -R servidor`.
- El servicio es `sshd` en Rocky y `ssh` en Ubuntu; la configuración, `/etc/ssh/sshd_config` (y `sshd_config.d/`).
- El registro (`journalctl -u sshd` o `-u ssh`) muestra cada entrada y cada intento fallido.
</Resumen>
