**MySQL** fue durante veinte años la base de datos libre de la web. Cuando Oracle la compró, en 2010, su creador original arrancó **MariaDB** a partir del mismo código, y hoy es la que traen Rocky, Ubuntu y casi todas las distribuciones. Las dos siguen siendo casi totalmente compatibles: los mismos comandos (`mysql`, `mysqldump`), el mismo protocolo y casi el mismo SQL, así que lo que aprendas acá sirve para las dos. La mayoría de las aplicaciones PHP (WordPress, Moodle, Nextcloud, muchos sistemas de gestión) la usan.

## Instalar y entrar

| | Rocky Linux 10 | Ubuntu 26.04 |
|---|---|---|
| Instalar | `dnf install mariadb-server` | `apt install mariadb-server` |
| Versión | MariaDB 10.11 | MariaDB 11.8 |
| Servicio | `mariadb` (hay que habilitarlo y arrancarlo) | `mariadb` (arranca solo) |
| Configuración | `/etc/my.cnf.d/mariadb-server.cnf` | `/etc/mysql/mariadb.conf.d/50-server.cnf` |
| Escucha de fábrica | en todas las direcciones | solo en `127.0.0.1` |
| Datos | `/var/lib/mysql` | `/var/lib/mysql` |
| Log de errores | `/var/log/mariadb/mariadb.log` | el journal (`journalctl -u mariadb`) |

Desde hace varias versiones, **root no tiene contraseña**: entra por **unix_socket**, que comprueba que el usuario de Linux sea root. Por eso `sudo mysql` entra directo, y `mysql -u root` con tu usuario dice "Access denied". Es más seguro que una contraseña de root guardada en algún lado. `mariadb-secure-installation` termina de ajustar lo demás (borrar usuarios anónimos y la base de prueba, si los hay).

Un detalle de Rocky: MariaDB 10.11 usa de fábrica el juego de caracteres latin1, que no guarda emojis ni algunos caracteres de otros idiomas. Creá las bases con `CHARACTER SET utf8mb4`, o agregá `character-set-server = utf8mb4` en el archivo del servidor (Ubuntu ya lo trae así).

## Cuentas: usuario más origen

En MariaDB una cuenta no es solo un nombre: es **usuario @ host**. `'tienda_app'@'localhost'` y `'tienda_app'@'192.168.10.%'` son dos cuentas distintas, con contraseñas y permisos independientes. El host puede ser `localhost` (por el socket, en el mismo servidor), una IP, una red con `%` o `%` solo (cualquier origen, a evitar).

```sql
CREATE DATABASE tienda CHARACTER SET utf8mb4;
CREATE USER 'tienda_app'@'192.168.10.%' IDENTIFIED BY 'una-clave-larga';
GRANT SELECT, INSERT, UPDATE, DELETE ON tienda.* TO 'tienda_app'@'192.168.10.%';
SHOW GRANTS FOR 'tienda_app'@'192.168.10.%';
SELECT user, host, plugin FROM mysql.user;
```

El principio es el de siempre, **mínimo privilegio**: una cuenta por aplicación, solo sobre su base, y solo con lo que la aplicación necesita para funcionar. Nunca la aplicación conectada como root, y nunca `GRANT ALL ON *.*` "para que ande". Si la aplicación necesita crear sus tablas al instalarse, se le dan `CREATE, ALTER, INDEX` durante la instalación y después se le sacan con `REVOKE`.

## Conexiones desde otros servidores

Lo habitual es que la aplicación corra en otro servidor. Para eso hacen falta tres cosas:

1. Que MariaDB escuche en la red: en Ubuntu, cambiar `bind-address = 127.0.0.1` por la IP del servidor (o `0.0.0.0`) y reiniciar. En Rocky ya escucha en todas.
2. Que el firewall deje pasar el 3306 (servicio `mysql` en firewalld), idealmente **solo** desde los servidores de aplicación: en firewalld, con una zona que tenga esas direcciones de origen, o una regla con `source address`.
3. Una cuenta para el origen de la aplicación (`'app'@'192.168.10.%'` o la IP exacta).

MariaDB **nunca** se publica en internet: si alguien de afuera necesita los datos, se le da una API, una VPN o una réplica, no el puerto 3306.

Para no escribir la contraseña en la línea de comandos (queda en el historial y se ve en la lista de procesos), las herramientas leen `~/.my.cnf`, con permisos 600:

```ini
[client]
host = db01
user = tienda_app
password = una-clave-larga
```

<Resumen>
- MariaDB es el sucesor libre de MySQL y casi totalmente compatible. Rocky 10: 10.11; Ubuntu 26.04: 11.8.
- root entra por unix_socket (sudo mysql). Configuración en /etc/my.cnf.d (Rocky) o /etc/mysql/mariadb.conf.d (Ubuntu).
- Una cuenta es usuario@host; CREATE USER, GRANT con lo justo sobre base.*, SHOW GRANTS y REVOKE.
- Para conexiones remotas: bind-address, firewall solo desde las aplicaciones y una cuenta para ese origen. Nunca en internet.
- Errores: 2002 (no llega), 1130 (no hay cuenta para ese origen), 1045/1698 (identidad), 1142 (permisos).
- Credenciales en ~/.my.cnf con permisos 600.
</Resumen>
