Las PC de las personas son, casi siempre, Windows, y Windows comparte archivos con su propio protocolo: **SMB**. **Samba** es la implementación de SMB para Linux: con ella, una carpeta de un servidor Linux aparece en el Explorador de Windows como `\\files01\contabilidad`, se puede asignar a una letra (`Z:`) y respeta usuarios y permisos. En el módulo 3.4 viste los recursos compartidos desde Windows Server; acá vas a hacer lo mismo desde Linux, que en muchas empresas medianas es el servidor de archivos.

## Instalar y configurar

```bash
sudo dnf install samba                    # Rocky: el servicio es smb
sudo apt install samba                    # Ubuntu: el servicio es smbd y arranca solo
sudo systemctl enable --now smb           # (en Ubuntu, smbd)
sudo firewall-cmd --permanent --add-service=samba && sudo firewall-cmd --reload
```

Todo se configura en `/etc/samba/smb.conf`: una sección `[global]` con lo general y una sección por cada recurso compartido.

```ini
[global]
	workgroup = EMPRESA
	security = user

[contabilidad]
	comment = Contabilidad
	path = /srv/samba/contabilidad
	valid users = @contabilidad
	writable = yes
	create mask = 0660
	directory mask = 2770
```

- `path`: la carpeta que se comparte.
- `valid users`: quién puede entrar. Con `@` es un grupo; sin `@`, un usuario.
- `writable = yes` (o `read only = no`, que es lo mismo): de fábrica, los recursos son de solo lectura. `write list` da escritura a algunos en un recurso que es de lectura para el resto.
- `create mask` y `directory mask`: los permisos máximos de lo que se crea (de fábrica, 0744 y 0755). `force group` hace que todo lo nuevo sea de un grupo (lo mismo que el SGID de la carpeta).
- `guest ok = yes`: se puede entrar sin usuario. Solo para carpetas públicas de solo lectura.

Cada vez que se toca el archivo, **testparm** revisa la sintaxis y muestra cómo lo entendió Samba. Es importante porque Samba **ignora en silencio** los parámetros mal escritos: un `writeable2 = yes` no da error al arrancar, simplemente no hace nada. Los cambios en los recursos los toma Samba solo, en unos minutos; para aplicarlos enseguida, `sudo smbcontrol all reload-config` (o reiniciar el servicio).

## Las cuentas de Samba

Windows no manda la contraseña igual que Linux, así que Samba guarda sus propias contraseñas. Pero cada cuenta de Samba tiene que corresponder a un **usuario de Linux**, porque los permisos de los archivos se aplican con ese usuario.

```bash
sudo smbpasswd -a ana      # crea la cuenta (pide la contraseña dos veces)
sudo smbpasswd -d ana      # la deshabilita (-e la vuelve a habilitar)
sudo smbpasswd -x ana      # la borra
sudo pdbedit -L            # lista las cuentas
```

Si en la empresa hay un dominio de Active Directory (el del módulo 3.3), lo habitual no es crear cuentas en Samba, sino **unir el servidor al dominio**: con `realm join` y `security = ads`, las personas entran con su usuario y contraseña de Windows, y los grupos del dominio sirven en `valid users`. Es un tema con varias piezas (Kerberos, SSSD o winbind, el mapeo de uid) y queda para más adelante; lo que cambia es de dónde salen las cuentas, no cómo se arma el recurso.

## Los cinco controles

Desde Windows, casi cualquier problema se ve como "No tiene permiso" o "No se encuentra la ruta de acceso". Por eso conviene probar en el propio servidor con **smbclient**, que muestra el error exacto:

```bash
smbclient -L //localhost -U ana                   # qué recursos ve ana
smbclient //localhost/contabilidad -U ana -c ls   # entrar y listar
```

El paso que más se olvida en Rocky es **SELinux**: smbd solo puede tocar archivos con la etiqueta `samba_share_t`. Una carpeta nueva en `/srv` tiene otra, y el resultado es un recurso que aparece pero no deja ver nada:

```bash
sudo semanage fcontext -a -t samba_share_t '/srv/samba(/.*)?'
sudo restorecon -Rv /srv/samba
```

Para compartir las carpetas personales hay un booleano (`samba_enable_home_dirs`), y para casos especiales, `samba_export_all_ro` y `samba_export_all_rw`, que dejan a Samba leer (o escribir) cualquier archivo: mejor no usarlos.

## Desde los clientes

- **Windows**: en el Explorador, `\\files01\contabilidad`; para una letra fija, `net use Z: \\files01\contabilidad /persistent:yes` o una GPO de unidades asignadas (módulo 3.3).
- **Linux**: con el paquete `cifs-utils`, `mount -t cifs`. Todo el montaje usa una sola cuenta de Samba, y los archivos se ven con el dueño y los permisos que digan las opciones, no los del servidor:

```bash
sudo mount -t cifs //files01/contabilidad /mnt/conta -o credentials=/root/.smb-conta,uid=ana,gid=contabilidad
```

El archivo de credenciales (`username=` y `password=`, con permisos 600) evita dejar la contraseña en `/etc/fstab` o en el historial. Sin `uid=` y `gid=`, todo aparece como de root y los demás usuarios del equipo no pueden escribir.

<Resumen>
- Paquete samba; servicio smb (Rocky) o smbd (Ubuntu); firewall: servicio samba (445).
- smb.conf: [global] y una sección por recurso con path, valid users (@grupo), writable, create mask, directory mask; testparm después de cada cambio.
- Cuentas: smbpasswd -a (atada a un usuario de Linux), -d, -x; pdbedit -L. Con Active Directory, el servidor se une al dominio.
- Cinco controles: red, cuenta, recurso, SELinux (samba_share_t) y la carpeta. smbclient muestra en cuál falla.
- Clientes: \\servidor\recurso en Windows; mount -t cifs con credentials=, uid= y gid= en Linux.
</Resumen>
