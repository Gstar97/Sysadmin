## La versión vigente: Windows Server 2025

**Windows Server 2025** salió en noviembre de 2024 y es la versión de canal de servicio a largo plazo (**LTSC**): Microsoft le da cinco años de soporte principal (con mejoras) y cinco de soporte extendido (solo seguridad). En fechas: soporte principal hasta el **13 de noviembre de 2029** y extendido hasta el **14 de noviembre de 2034**.

Las versiones anteriores siguen andando en muchas empresas, y conviene saber en qué estado están:

- **Windows Server 2022**: terminó su soporte principal en octubre de 2026. Sigue recibiendo parches de seguridad hasta 2031.
- **Windows Server 2019**: en soporte extendido hasta enero de 2029.
- **Windows Server 2016**: su soporte extendido termina en **enero de 2027**. Si te toca uno, ya hay que planificar el reemplazo.

Es como el service oficial de un auto: mientras está en garantía (soporte principal) te arreglan todo; después, solo lo que hace a la seguridad; cuando se termina, si algo falla, estás solo. Donde la comparación no llega: un auto viejo sin service sigue andando igual, pero un servidor sin parches queda cada mes más expuesto a ataques conocidos.

Windows Server 2025 permite actualizar "en el lugar" desde 2012 R2, 2016, 2019 o 2022, pero en la práctica lo habitual es instalar uno nuevo y migrar los roles: así el servidor arranca limpio y siempre tenés el viejo para volver atrás.

- **Essentials**: para empresas chicas. Viene instalada en el servidor que vende el fabricante (no se compra suelta), admite hasta **25 usuarios y 50 dispositivos**, un solo procesador de hasta 10 núcleos, y no necesita CAL. Si la empresa crece, se pasa a Standard.
- **Standard**: la más usada. Tiene todos los roles que vas a ver en este nivel (Active Directory, DNS, DHCP, archivos, Hyper-V). La licencia te da derecho a **dos máquinas virtuales** con Windows Server por cada vez que licenciás todos los núcleos del equipo.
- **Datacenter**: lo mismo que Standard más **máquinas virtuales ilimitadas** y algunas funciones de centro de datos: Storage Spaces Direct (almacenamiento repartido entre varios servidores), redes definidas por software y Storage Replica sin los límites de Standard.

Existe también **Datacenter: Azure Edition**, que solo corre en Azure o en Azure Local (los equipos de Microsoft para tener "Azure en tu sala de servidores"). *Para más adelante*, en el Nivel 7.

## Cómo se licencia: por núcleos

Standard y Datacenter se licencian **por núcleo físico** del servidor, con dos mínimos: **8 núcleos por procesador** y **16 por servidor**, aunque el equipo tenga menos. Las licencias vienen en paquetes de **2 y de 16 núcleos**.

Un ejemplo: un servidor con un procesador de 12 núcleos. Tiene 12, pero el mínimo por servidor es 16: hay que comprar **16 núcleos** (un paquete de 16). Con Standard, eso cubre el servidor y 2 máquinas virtuales. Si querés 4 máquinas virtuales, hay que licenciar todos los núcleos **otra vez**: 32 núcleos. Para 6, tres veces: 48.

Con Datacenter licenciás los 16 núcleos una sola vez y las máquinas virtuales son ilimitadas. Datacenter cuesta bastante más (precios sugeridos de Microsoft para 16 núcleos: US$ 1.176 Standard y US$ 6.771 Datacenter; los reales dependen de dónde compres), así que hay un punto de equilibrio: en un servidor de 16 núcleos, Datacenter empieza a convenir desde unas **11 máquinas virtuales**.

### Las CAL: quién usa el servidor

Además de los núcleos, cada **persona o dispositivo** que usa los servicios del servidor (iniciar sesión en el dominio, abrir una carpeta compartida, imprimir) necesita una **licencia de acceso de cliente (CAL)**. Hay dos tipos:

- **CAL de usuario**: una por persona, que puede entrar desde la notebook, la PC y el celular.
- **CAL de dispositivo**: una por equipo, que lo pueden usar varias personas (una PC de mostrador que usan tres turnos).

Se elige la que da menos cantidad. Ojo con dos detalles: las CAL tienen que ser de **Windows Server 2025** (o más nuevas); las de 2022 no sirven para un servidor 2025. Y el Escritorio remoto (RDS) lleva sus propias CAL, aparte.

Es como la entrada a un club: el servidor es el edificio (los núcleos), pero cada socio que entra necesita su carnet (la CAL). Donde no llega la comparación: nadie controla en la puerta; Windows deja entrar igual aunque falten CAL. Es una obligación del contrato, y en una auditoría de licencias se cuentan.

### Pago por uso con Azure Arc

Desde Windows Server 2025 hay otra forma: conectar el servidor a **Azure Arc** (el servicio de Microsoft para administrar servidores propios desde Azure) y **pagar por mes según los núcleos que usa**, sin comprar núcleos ni CAL (salvo las de Escritorio remoto). Conviene para servidores que van a vivir poco o cuando la empresa prefiere un gasto mensual a una compra. Con Arc también se puede contratar **Hotpatch**, que instala la mayoría de los parches de seguridad sin reiniciar. Los dos los vas a ver en el módulo 3.5; los precios cambian seguido, así que consultalos en el momento.

## Con escritorio o sin escritorio

Al instalar, elegís entre dos opciones, y la decisión es **para siempre**: desde Windows Server 2016 no se puede pasar de una a otra sin reinstalar.

- **Server Core** (la opción por defecto): sin escritorio ni Explorador. Al iniciar sesión aparece una consola con **sconfig**, un menú de configuración, y PowerShell. Se administra sobre todo a distancia, desde otra computadora. Ocupa menos disco y memoria, tiene menos componentes que actualizar (menos reinicios) y menos lugares por donde atacarlo.
- **Experiencia de escritorio**: la de siempre, con escritorio, Explorador, Administrador del servidor y las consolas gráficas. Hace falta para algunos programas de terceros que solo traen instalador gráfico, y es más cómoda para aprender.

La recomendación de Microsoft, y la de este curso, es **Server Core para todo lo que se pueda**: controladores de dominio, DNS, DHCP, servidores de archivos, Hyper-V. En este nivel vas a instalar uno de cada uno, y vas a ver que el Core se maneja muy bien con PowerShell y Windows Admin Center.

### Lo que pide el equipo

Lo mínimo que pide Windows Server 2025: un procesador de 64 bits de 1,4 GHz con las instrucciones SSE4.2 y POPCNT (cualquier procesador de los últimos diez años), 512 MB de RAM para Server Core o 2 GB con escritorio, y 32 GB de disco. Son mínimos para que arranque, no para trabajar: para un laboratorio, calculá 2 a 4 GB de RAM y 60 GB de disco por máquina virtual.

Para practicar no hace falta comprar nada: Microsoft ofrece una **versión de evaluación de 180 días** que se descarga del Centro de evaluación. Cuando se vence, se puede convertir a una licencia comprada sin reinstalar. *Para más adelante*: las formas de activar en una empresa (KMS, claves MAK y la activación automática de máquinas virtuales en hosts Datacenter).

<Resumen>
- Windows Server 2025 es la versión LTSC vigente: soporte principal hasta 2029 y extendido hasta 2034.
- Essentials (hasta 25 usuarios y 50 dispositivos, sin CAL, viene con el equipo), Standard (2 VM por cada vez que licenciás todos los núcleos) y Datacenter (VM ilimitadas y funciones de centro de datos).
- Se licencian todos los núcleos físicos: mínimo 8 por procesador y 16 por servidor, en paquetes de 2 y de 16.
- Cada persona o dispositivo que usa el servidor necesita una CAL de 2025; el Escritorio remoto lleva las suyas.
- Con Azure Arc se puede pagar por uso, sin comprar núcleos ni CAL.
- Server Core es la opción por defecto y la recomendada; no se puede cambiar a escritorio (ni al revés) sin reinstalar.
